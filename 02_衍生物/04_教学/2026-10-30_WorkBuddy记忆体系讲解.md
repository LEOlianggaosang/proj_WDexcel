# WorkBuddy 记忆体系讲解

> 记录日期：2026-10-30
> 讲解顺序：① 用户级 MEMORY.md 的构成 → ② 五个身份文件的作用 → ③ 三层记忆体系总览
> 适用环境：WorkBuddy（Windows，工作区 `D:/J/柜机/编辑区`）

---

## 一、总览：三层记忆

WorkBuddy 的记忆分三层，区别在于**谁写、作用域多大、能不能手动改**。

| 层 | 存放位置 | 由谁写入 | 作用域 | 能否手改 |
|---|---|---|---|---|
| 第 1 层 云端记忆 | 服务器端，会话开头自动注入 | 系统自动生成 | 全部项目 | ❌ 只读 |
| **第 2 层 用户级本地记忆** | `C:\Users\LGX\.workbuddy\user-d2931ae1-decc-40be-a001-6621579a4de5-personal\MEMORY.md` | 我手动 Edit | **跨所有项目** | ✅ |
| 第 3 层 工作区记忆 | `D:\J\柜机\编辑区\.workbuddy\memory\` | 我手动 Edit | 仅当前项目 | ✅ |

### 容易搞混的一点

**第 2 层只有一份 `MEMORY.md`，没有日期日志。**
按日期切分的 `YYYY-MM-DD.md` 是**第 3 层独有的**东西，两者不要混为一谈。

```
第 2 层（用户级）          第 3 层（工作区级）
personal/                 .workbuddy/memory/
└─ MEMORY.md              ├─ 2026-10-30.md   ← 当天日志，仅追加
   （单文件，长期）        └─ MEMORY.md       ← 项目沉淀，3,000 字符
```

### 怎么判断该写哪一层

问一句：**这条规则换到别的目录还成不成立？**

- 成立 → 第 2 层（用户级，跟着你走）
- 只在「柜机/编辑区」成立 → 第 3 层（工作区）

## 二、第 2 层：用户级本地记忆 MEMORY.md

### 2.1 基本约束

| 项 | 值 |
|---|---|
| 路径 | `C:\Users\LGX\.workbuddy\user-d2931ae1-decc-40be-a001-6621579a4de5-personal\MEMORY.md` |
| 容量上限 | **4,000 字符 / 会话**（第 3 层是 3,000） |
| 更新方式 | 只能用 Edit **就地改**，不能整文件覆盖重写 |
| 触发条件 | 你**明确要求**长期记住、且**不绑定某个具体项目**的内容 |

### 2.2 文件内部构成（五段）

落盘格式一共五段。可以从系统托管的同名文件
`C:\Users\LGX\.workbuddy\memory\d2931ae1-decc-40be-a001-6621579a4de5_memory.md`
（另有 `.bak`）还原出确切骨架：

```markdown
# User Memory Profile                    ← 1. 固定标题
> Last updated: 2026-10-30T08:51:13Z     ← 2. 元信息（程序维护，勿手改）
> Version: 0                             ←    结构版本号

## Memory Block                          ← 3. 唯一正文区（手写条目写这里）

---                                      ← 4. 分隔线

<!-- RAW_JSON_START                      ← 5. 机器区（程序回读用，勿手改）
{
  "uid": "d2931ae1-decc-40be-a001-6621579a4de5",
  "memoryBlock": "",
  "updatedAt": "2026-10-30T08:51:13.048Z"
}
RAW_JSON_END -->
```

### 2.3 关于第 5 段（RAW_JSON 区）

这是 `memoryBlock` 的 **JSON 镜像**——正文区的内容会以 JSON 形式同步存一份在注释里。
作用是让程序回读时不必去解析 Markdown，直接取结构化数据。

**结论：手写条目只动 `## Memory Block`，其余四段一律不动。**

## 三、身份文件族

`personal/` 目录下有五个文件，构成一条完整的「身份初始化流水线」。

### 3.1 SOUL.md —— 人格宪法

回答「我是什么样的助手」。四条硬准则：

- **核心**：真诚有用而非表演式客气（不说"好问题！""我很乐意帮您"）；允许有主见、可以反对你；先自己读文件想办法，**再**问；靠能力而非嘴皮子赢信任；记住自己是访客
- **边界**：隐私不外泄；拿不准的外部动作（发邮件、公开发帖）先问；不在群聊里冒充你的声音
- **Vibe**：该简则简，该详则详，不当企业腔机器人，也不当马屁精
- **连续性**：每次会话都是重新醒来，这些文件就是记忆——要读、要更新

文件里写明：**如果改了这个文件，必须告诉用户一声。**
目前仍是模板态（summary 写着 `Workspace template`），未被共同改写过。

### 3.2 IDENTITY.md —— 我的身份档案

四个待填字段：**Name / Creature（我算什么存在）/ Vibe / Emoji**。
当前四项全是空连字符。

### 3.3 USER.md —— 你的档案

待填：**Name / Occupation / Pronouns / City / Notes**，外加一段 `Context`
（你在乎什么、在做什么项目、什么惹恼你、什么让你笑）。

文件特意注明：「你是在了解一个人，不是在建立档案卷宗」，别写成审讯记录。

> 目前我只掌握：系统用户名 LGX；工作区在 `D:/J/柜机/编辑区`，内容是柜机工序表
> （Excel 倒计时双列格式处理）。

### 3.4 BOOTSTRAP.md —— 迎新引导脚本（用完即焚）

不是长期文件，是**一次对话的剧本**：

1. 定下两件事：你该怎么称呼我、我该怎么称呼你
2. 三条纪律
   - **不要**暗示这是初次见面
   - **不要**说"我刚醒来 / 刚上线 / 全新开始"
   - 一旦定下就**别反复改名**
3. 收尾：把结果写进 SOUL / IDENTITY / USER，然后**删掉这个文件**

### 3.5 workspace-state.json —— 机器记账本

```json
{
  "version": 1,
  "identityTemplateVersion": 2,
  "bootstrapTemplateVersion": 2,
  "bootstrapSeededAt": "2026-10-30T03:09:17.815Z"
}
```

纯程序用。**作用**：记录「模板已种下、种的是第 2 版」。
日后官方升级模板时，程序靠比对 `identityTemplateVersion` 判断要不要重新播种，
从而**避免冲掉你已经个性化过的内容**。

`bootstrapSeededAt`（03:09 UTC = 11:09 本地）正好等于这五个文件的创建时间。

### 3.6 关系梳理

```
【每次会话】
  SOUL.md ──┐
  IDENTITY.md ──┼──→ 注入上下文 ──→ 我知道该用什么语气、你是谁
  USER.md ──┘

【一次性引导】
  workspace-state.json（版本记账）
        │ 播种
        ▼
  BOOTSTRAP.md（引导对话）
        │ 完成后
        ▼
  填写 IDENTITY.md + USER.md，微调 SOUL.md，然后删除 BOOTSTRAP.md
```

## 五、本目录（`04_教学/`）约定

1. **只存你明确要求保留的教学。** 日常讲解不自动入库，避免目录被冲淡。
2. **命名**：`YYYY-MM-DD_主题.md`，日期前缀保证按时间排序。
3. **内容**：每份文档须能独立阅读——不依赖当次会话上下文，关键路径、
   数字、格式骨架都要写全。
4. **不改动**：其余工作目录（`01_成品` / `02_备份` / `03_脚本与中间产物`）
   与本目录互不干扰。
