## 二、数据红线

| # | 规则 | 实证依据 |
|---|---|---|
| 1 | **配时列不得由脚本自动生成** | 取整方向不一致：`排水30`(0.5分)→1 上取、`定时加热90`(1.5分)→1 **下取**、`排水10`→0 下取。它是**人工配时值** |
| 2 | 「÷60」只能做**反查**，偏差大时报警不自动修正 | 同上 |
| 3 | 第 4 行总时长 = **自动校验锚点**：总和必须 =「开关矩阵 × 配时列」 | A3 裁决。Glass Express 的 105 即由此反推证实（标称 115 系笔误） |
| 4 | 遇 **MINI 变体续行**（A 列无序号的参数变体行）先查时长 | 它是 +2 偏差真凶：Self-cleaning 改动前合计 102 vs 标称 100，差的正是两个续行的 1+1 |
| 5 | **双速电机列原样保留，双列区推导不使用它** | 预留项，当前机型无此配置，列内写「静止」不是矛盾 |

**上下限设计的含义**：每步耗时是**占总倒计时的允许区间**，不是定值。实机跑偏出界即异常——这是用户跑机对照的判读依据。

## 四、已知坑

| 坑 | 说明 |
|---|---|
| **md5 不可用** | openpyxl 每次保存更新 `docProps/core.xml` 时间戳，同内容也出不同 md5。必须**逐格比对** |
| **StyleProxy 不可 copy** | `deepcopy(font)` 会 RecursionError，须显式重建 Font |
| **A3 求和校验发现不了丢行** | 曾出现 6 行丢失「序号+描述」只留参数与配时，数值仍在所以总和照旧对得上。须加**完整性检查**：有参数/配时却无描述 = 缺陷 |
| **合并格遮内容** | MINI 合并格会把下一行真实序号遮住（89Mins 应显示 35/39，实际显示 34/38） |
| **回归校验的自证陷阱** ⚠️ | **回归必须拿 `01_源文件/` 的模板分栏当基准**，不能拿成品——成品已被上一轮落笔改成规则的样子，那样永远 0 差异。2026-11-01 已修：此前「Intensive 0 差异」是假象，改用源文件基准后暴露出 76 处真实分歧 |
| **普通加载拍平富文本** ⚠️ | 不带 `rich_text=True` 的 load+save 会把行内红字压平成纯文本。**验收轮实测：范围外 8 张表 108 处被链路拍平**（违反 B2）。对策：末段 `restore_outscope()` 按坐标从源回拷；富文本签名比对须逐块含颜色 |
| **`Normal ` 尾随空格** | 表名带空格，字典键按 `Normal` 匹配不上 → autoFilter 恢复漏网。凡按表名建字典，先 `repr` 核对 |
| **Rapid 的 `vmlDrawing1.vml`** | 隐藏批注框重写后丢失。用户裁决**不保真**；验收轮 V13 已显式删除全部批注 |
