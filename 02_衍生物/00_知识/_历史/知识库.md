## 一、表格长什么样

### 1.1 概念层级（自上而下）

```
本机型            = 工作簿物理身份（第 1 行标题）
  └ 洗涤菜单      = 工作表标签。如 Intensive / Glass / 89Mins
      └ 洗涤阶段  = B 列合并单元格：预洗 → 主洗 → 漂洗 → 干燥
          └ 洗涤步骤 = A 列序号，一行一步
              ├ 步骤描述 = C 列（做什么）
              └ 步骤参数 = D 列（设定值，形式决定语义）
  └ 电控可选功能  = E 列起开关矩阵（分组），打开即改变时序与总时间
  └ 步骤倒计时配时 = 例 L 列（分钟），设计含**上下限**
  └ 双速电机      = 例 M 列。**预留项**，与风机无关，当前机型无此配置
```

实证标题（Intensive）：`E5平台欧洲60机双速非交替（A++）洗涤时序`

### 1.2 区域定位公式（列位置浮动，必须现算）

```
开关矩阵  ：E 列起，宽度 = 分组数（各分栏 1～7 组不等）
源倒计时  ：紧接开关矩阵之后
双速电机  ：紧接源倒计时之后
双列区    ：紧接双速电机之后
```

| 分栏 | 开关矩阵 | 源倒计时 | 双速电机 | 双列区 |
|---|---|---|---|---|
| Intensive | E–K (7 组) | L | M | N–W |
| Glass | E–K (7 组) | L | M | N–W |
| Rapid | E–F (2 组) | G | H | I–L |
| 89Mins | E–K (7 组) | L | M | N–W |
| Soak | E (1 组) | F | G | H–I |
| Self-cleaning | E (1 组) | F | G | H–I |

> **辅助列一律清空**：辅助列 `=SUM(...)` 求的「该组总时长」，双列区累计列终值也是同一个数，纯冗余。

### 1.3 阶段列（B 列，易漏的一层）

四段合并：预洗 → 主洗 → 漂洗 → 干燥。例 Intensive 为 `B5:B16` / `B17:B32` / `B33:B57` / `B58:B67`。
**插行删行必须同步调整这些合并区域。**

### 1.4 三条交付线（互不越界）

| 文档 | 定位 | 含什么 |
|---|---|---|
| **时序表** | 电控程序的洗涤过程部分 | 机型/菜单/阶段/步骤/描述/参数/电控可选功能/配时 |
| **规格书** | 面板交互规则 + 运行逻辑 | **不在本次范围**，仅作术语参照 |
| **双列区** | 用户跑机对照用 | 累计列 + 倒计时串，**不属于本体** |

## 二、本体怎么读

### 2.1 参数四类形式（结合描述判语义）

| # | 形式 | 例 | 语义 | 与配时列的关系 |
|---|---|---|---|---|
| ① | `纯数字` | `排水 30`、`洗涤 600` | 动作时长（秒） | ≈ ÷60（有取整异常，见下） |
| ② | `数字L` | `进水 3.9L` | 目标水量，**到位即完成** | 按流量估，多为 1 分；0.3/0.5L → 0 分 |
| ③ | `T数字/数字` | `T50/360` | 50℃ / **360 = 整步总时长（秒）**，温达后不提前跳步 | = 360÷60 = 6 分 |
| ④ | `纯 T数字` | `T69` | 只给目标温度，**温达即跳步**；配时是防失控上限 | 人工值。同 T69 有 19/14/10 三种——水温越高升温越快，逐行递减 |

**取整异常（证明配时列不可机械换算）**

| 参数 | ÷60 | 表上配时 | 方向 |
|---|---|---|---|
| `排水 30` / `45` | 0.5 / 0.75 | 1 | 上取 |
| `定时加热 90` | 1.5 | 1 | **下取**（与上相反） |
| `排水 10`、`静止 8` | <0.2 | 0 | 下取 |

→ **配时列是人工配时值**。脚本不得「÷60」生成，只能反查报警。

### 2.2 配时的上下限设计（A2 裁决）

「上下限」指**每个步骤占总倒计时的允许区间**，不是温度上下限。每步耗时是一个区间而非定值，实机跑偏出界即异常——这正是用户跑机对照时的判读依据。

### 2.3 第 4 行总时长 = 自动校验锚点（A3 裁决）

第 4 行总时长**可由「开关矩阵 × 配时列」反推**。因此 Glass Express 该是 105 还是 115 这类争议，由算法裁决而非人工猜（已反推证实 **105**，标称 115 系笔误）。

### 2.4 双速电机

**预留项**，与风机无关，当前无此配置。取值现状「静止 / 高速」（Intensive 干燥段整段写「静止」，含风机行——**不是矛盾**）。
**处理：本体原样保留，双列区推导不使用该列。**

### 2.5 措辞新旧对照（C 列）

| 新版（模板：Intensive / Glass） | 旧版（待改） |
|---|---|
| `洗涤分配(主洗)` + `洗涤加热（定时加热）`（**两行**） | `洗涤分配加热（主洗）`（一行） |
| `洗涤加热（定温加热-温达剩洗）` | `洗涤加热`（参数 `T55/420`） |
| `洗涤加热（定温加热-温达跳步）` | `洗涤加热`（参数 `T69`） |
| `洗涤加热分配（漂洗)分配器：开10秒停8秒累计动作6次` | `洗涤加热分配（漂洗)` |
| `再生进水风机（非再生跳步）` | `再生(电子可调)` |
| `冷风进水排水（边进边排-进完跳步）（非再生跳步）` | （旧版暂无对应） |

**参数形式 → 加热语义（判定表）**

| D 列形式 | 加热类型 | 标记 |
|---|---|---|
| `T数字/数字` | 定温加热-**温达剩洗** | 黄填充 + 红字 |
| `纯 T数字` | 定温加热-**温达跳步** | 黄填充 + 红字 |
| `纯数字` | **定时加热** | **绿填充** |

### 2.6 MINI 变体续行

同一工序的参数变体行，**A 列序号为空**。它是「辅助列 +2 偏差」的真凶（Self-cleaning 改动前合计 102 vs 标称 100，差的正是两个续行的 1+1）。
**处理（U2 裁决）**：删续行，其参数吸收进拆出的 `洗涤分配(主洗)`——「拆一行描述、配一行参数，正好匹配两行」。

## 三、双列区怎么建（衍生物）

| 术语 | 指什么 | 规则 |
|---|---|---|
| **累计列** | 每组 2 列中的第 1 列 | 只累加「该组执行且配时≠0」的行 |
| **倒计时列** | 第 2 列 | 格式见下 |
| **倒计时串** | 单格内容 | `本步耗时/剩余`，如 `6/2:42`；归零 `end` |
| **组名行** | 第 3 行 | 组名写**第 2 列**，第 1 列留空但保留框线 |
| **起值行** | 第 4 行 | 写 `0/总时长`，如 `0/2:50` |
| **端行** | 该组最后一行 | 统一写 `1/end` |

`6/2:42` 读作：本步跑 6 分钟，跑完还剩 2 小时 42 分。

## 四、颜色在说什么

### 4.1 填充与红字 = 「这行为什么被改过」的编码

> 反查母表《普通版从这里派生》逐行差分确证：**仅数值微调的行一律不着色**
> （水量 3.4→3.9L、洗涤 1200→600、干燥段秒数重排）。只有**改动性质**变了才着色。

**① 填充色 = 改动性质**

| 色 | 性质 | 实测例 |
|---|---|---|
| 🟩 绿 `FF92D050` | **结构性改动**：拆行、动作方式重写、参数性质变化 | `洗涤分配加热（主洗）`拆两行；`再生(电子可调) 120` → `再生进水风机 0.5L`（秒数→水量） |
| 🟨 黄 `FFFFFF00` | **参数/描述级改动** | `T50` → `T50/360`；`洗涤加热` → `…（定温加热-温达剩洗）` |
| 无 | 仅数值微调 | 水量 L 数、洗涤秒数 |

**② 填充横向范围 = 波及范围**

- **C–M 整行**：参数被改，波及开关矩阵/配时/电机（温达剩洗、分配器、再生、冷风）
- **C–D**：只有描述与参数被改（温达跳步——参数 `T69` 本身没变；89Mins 静止特例）

**③ 红字 = 逐格点名被改的值**

| 落点 | 含义 |
|---|---|
| `C` | 描述被改 |
| `D` | 参数被改 |
| `D + 配时列` | 参数与配时都被改（再生、冷风） |
| `D–M` | 加热参数形式被改写（定温加热） |
| `C + D` | 描述与参数都被改（干燥段静止/风机） |

**④ 灰填充** `theme0 tint-0.15`：双列区两列，该组无此步骤（空值 + 灰底同时出现）。
**⑤ 不托管行**：干燥段普通 `静止`/`风机` 模板标法不统一 → **脚本不动，保留人工原样**。

### 4.2 字体色

| 色 | 触发 |
|---|---|
| 红 `FFFF0000` | ① 定温加热类；② **逻辑与其他分栏不同、需特别提示**的行 |
| 蓝 `FF00B0F0` | 进水类步骤 |
| 绿 `FF92D050` | 端点（起值行、端行） |

> 红字第 ② 类用法：本质是「视觉性强调」，不限于加热。
> 实例：89Mins 干燥段三段 `静止` 不补风机，与强力/晶亮模式不同——**是有意设计，不是错误**，
> 正因逻辑不同才需黄填充 + 红字双标。跨分栏对比时，形态不同 ≠ 错了。

### 4.3 分栏标签色

绿（`9BBB59`）= 已维护完成。`Auto` 红、`Self-cleaning` 黄已按裁决处理（Auto 清红、Self-cleaning 改绿）。

### 4.4 干燥/再生段两种模式（易错点）

| 模式 | 分栏 | 形态 |
|---|---|---|
| 强力/晶亮 | Intensive、Glass | `再生进水风机` → `静止`(长) → `风机` ×2 → … |
| 89 分钟 | 89Mins | `再生` → `静止`×3 → … **不补风机** |

## 五、分组术语

| 术语 | 含义 |
|---|---|
| **Null** | 默认时序（无附加功能） |
| **ExtraDry** / **StrDry** | 加强烘干（StrDry 仅 1Hour 用） |
| **Energy(1/2)** / **1/2** / **WHR-HALF** | **半载** |
| **Express** | 快速 |
| **StrWash** | 加强洗 |
| MoreRin / MorePre | 存在但**双列区不建这两组**（每分栏只做它本来就有的组） |

**半载概念**（2026-11-01 用户澄清）：回答的是「机器**没有分层洗功能**时，用户只放一半餐具，时序该怎么处理」。
它是独立时序分组，**与节能无关**。

> ⚠️ 曾误记为「Energy = 节能，且 1Hour 同位置写作 StrDry」——两条都错。
> 数据证伪：1Hour 里 `StrDry`（第 6 列）与 `Energy(1/2)`（第 7 列）**并存**，不可能是异名。

## 六、操作纪律与已知坑

| 项 | 内容 |
|---|---|
| **回归校验** | 用重建算法重生成「已核对过」的数据逐格比对，差异应仅限已知笔误修正 |
| **格式保真审计** | 逐格比对源表与成品全部格式维度（17 项） |
| **已知坑：md5 不可用** | openpyxl 每次保存都更新 `docProps/core.xml` 时间戳，同内容也出不同 md5。必须逐格比对 |
| **已知坑：StyleProxy** | `deepcopy(font)` 会 RecursionError，须显式重建 Font |
| **已知损失** | Rapid 的 `vmlDrawing1.vml`（隐藏批注框）经 openpyxl 重写后丢失，用户已裁决**不保真** |
| **跨分栏对比** | 不同程序可以有不同模式，形态不同不等于错了 |

**仍在悬置**（详见 `PLAN.md`）：

- 温达跳步标法模板冲突：Intensive 标 C–M + 红 D–M，Glass 只标 C–D 无红 → 现按 **C–D** 执行
- 第 4 行 `D4 = 60` 语义未知（疑似机型代号）
- 自动门版是否同构 —— 第三步前置
