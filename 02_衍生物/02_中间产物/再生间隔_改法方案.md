### 干燥段目标顺序（成品二）

```
热漂后静置（若有） → 排水45/30 → 再生进水0.5L → 静止（再生间隔）
→ 前移步骤（进水排水2L / 排水10 / 进水排水2L / 排水45）
→ 自动开门/静止 120 → 自动开门静止/风机 …
```

即用户要求的「**先 0.5l 再 再生间隔 再 前移 再 自动开门**」。

### 1.3 通用拆分算法：开关公因式提取（用户 2026-11-03 裁决）

> 「提取的是**开关**的公因式，这部分能重新组合为**满开关的一步**和**分开关的两步**。」

干燥段风机块 = 若干 `(时长, 开关掩码)` 之和。拆再生间隔时：

1. **求公因式**：再生间隔 X 必须是**所有分组都有的**风机时长 → `X ≤ min(各组风机总时长)`，取 `X = REGEN_INTERVAL`（当前 600 秒）
2. **重组**：把风机块改写为 `X·全开关 + 余项`，余项用**最少个数的分开关步骤**表示
3. **拆门**：`X·全开关` → `静止（再生间隔）(X−120)·全开关` + `自动开门 120·全开关`
4. **余项**全部转为 `自动开门静止/风机`，相邻同掩码者合并
5. **若本无满开关的风机步**（如 89Mins），用集合恒等式重组：
   `A ∪ B = 全开关`、`A ∩ B = {ExtraDry}` ⟹ `600·A + 600·B = 600·全开关 + 600·{ED}`

**89Mins 实例**（A=6组即除Express、B={ED,Express}、C={ED}）：

```
原块 = 900·A + 600·B + 600·C
     = 600·A + 300·A + 600·B + 600·C
     = (600·A + 600·B) + 300·A + 600·C
     = (600·全开关 + 600·C) + 300·A + 600·C      ← 提取公因式 600·全开关
     = 600·全开关 + 300·A + 1200·C                ← 满开关一步 + 分开关两步
```

→ `静止（再生间隔）480[全]` + `自动开门/静止 120[全]` + `自动开门静止/风机 300[6组]` + `自动开门静止/风机 1200[ED]`
（原 `600[ED,Express]` 行系数为 0 → 删除；两个 ED 步合并为 1200）

**若已有满开关的风机步**（Intensive/Glass/Self-cleaning）：直接从该步扣 600，无需重组。

### 守恒恒等式（天然守恒，不增不减）

```
原风机总时长 = 静止（再生间隔）480 + 自动开门 120 + 剩余风机
               └────── 拆出的 10 分钟(600s) ──────┘
```

### 3.3 分组开关特征（由通用策略归纳）

| 分组 | 含义 | 干燥段风机特征 | 为什么 |
|---|---|---|---|
| **Null** | 基准程序 | 执行基准风机步 | 基准 |
| **ExtraDry** | 加强烘干 | **必是最长**：执行全部风机步 + 专属附加步 | 名即"额外干燥"，干燥段必然最重 |
| **Energy(1/2)** | 半载（非节能） | 长风机步被**缩短或替换**（Glass：1500→1200 走专属行） | 半载餐具少、含水少，干燥负担轻 |
| **Express** | 快速洗 | **跳过最长风机步**（89Mins 的 900 步不执行）；Glass/Intensive 只走满开关步 | 快速程序压缩干燥，故总时长最短 |
| **StrWash / MoreRinse / MorePre** | 加强洗 / 多漂洗 / 多预洗 | 干燥段与 Null 完全一致 | 差异在水洗段，不影响干燥 |

**推论**：干燥段差异只由 **ExtraDry（加）**、**Energy（减）**、**Express（跳）** 三者驱动，其余分组与 Null 同。
（实证：Intensive 仅 ED 多一步；Glass ED/Energy 各多一步且 Energy 值更小；89Mins Express 缺最长步。）

### 3.3 标记规则

- **黄填充**：前移步骤（0.5L 再生本身 → 最后排水本身及之前）
- **绿填充**：后移步骤（最后排水之后：自动开门 / 自动开门静止·风机）
- **红字**：涉及有无自动开门的步骤描述（拆出的静止、自动开门、后移步骤）
